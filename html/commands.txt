# deployment.yaml (Deployment)
Отвечает за создание и управление репликами вашего приложения.
apiVersion: apps/v1: Указывает версию API Kubernetes для Deployment.
kind: Deployment: Определяет тип ресурса как Deployment.
metadata.name: health-check: Имя Deployment, которое используется для идентификации этого ресурса в Kubernetes.
spec.replicas: 2: Определяет желаемое количество реплик (запущенных копий) вашего приложения. В данном случае, Kubernetes будет стремиться поддерживать две работающие копии вашего приложения.
spec.selector.matchLabels: app: health-check: Выбирает поды, которые должны управляться этим Deployment. Kubernetes использует метки (labels) для связывания подов с Deployment.
spec.template: Описывает шаблон для создания новых подов.
metadata.labels: app: health-check: Метки, которые будут присвоены каждому поду, созданному из этого шаблона. Эти метки используются для сопоставления подов с Deployment.
spec.containers: Определяет контейнеры, которые будут запущены в каждом поду.
name: health-check: Имя контейнера.
image: <ваш_логин_dockerhub>/<имя_вашего_образа>:latest: Образ Docker, который будет использоваться для запуска контейнера. Этот образ содержит ваше приложение.
ports: - containerPort: 80: Определяет порты контейнера. В данном случае, приложение слушает на порту 80 внутри контейнера.
livenessProbe и readinessProbe: Определяют зонды работоспособности и готовности контейнера.
httpGet: Указывает, что зонд будет отправлять HTTP GET-запрос на указанный путь и порт.
path: /health: Путь, на который будет отправляться запрос (в вашем приложении должен быть endpoint, отвечающий на этом пути).
port: 80: Порт, на который будет отправляться запрос.


# service.yaml (Service)
Обеспечивает доступ к вашим подам.
apiVersion: v1: Указывает версию API Kubernetes для Service.
kind: Service: Определяет тип ресурса как Service.
metadata.name: health-check-service: Имя Service.
spec.selector: app: health-check: Выбирает подов, к которым должен предоставлять доступ этот Service. Он использует те же метки, что и Deployment.
spec.ports: Определяет порты сервиса.
protocol: TCP: Указывает протокол TCP.
port: 80: Порт сервиса, который будет доступен извне.
targetPort: 80: Порт, на котором слушают контейнеры в подах.
spec.type: LoadBalancer: Определяет тип Service. LoadBalancer автоматически создает LoadBalancer у вашего провайдера облака (например, в AWS, GCP или Azure). Если нет LoadBalancer, замените на ClusterIP (как мы делали ранее).

# ingress.yaml (Ingress)
Обеспечивает внешний доступ к вашему сервису.
apiVersion: networking.k8s.io/v1: Указывает версию API Kubernetes для Ingress.
kind: Ingress: Определяет тип ресурса как Ingress.
metadata.name: health-check-ingress: Имя Ingress.
spec.rules: Определяет правила маршрутизации.
host: arch.homework: Хост, на который будет направляться трафик.
http.paths: Определяет пути и бэкенды для обработки трафика.
path: /health: Путь, на который будет направляться трафик.
pathType: Prefix: Указывает, что этот путь является префиксом.
backend.service.name: health-check-service: Имя Service, к которому будет направляться трафик.
backend.service.port.number: 80: Порт сервиса.

Вкратце: Deployment управляет подами приложения, Service обеспечивает доступ к подам внутри кластера, а Ingress обеспечивает внешний доступ к сервису, если он настроен. Они работают вместе, обеспечивая масштабируемость, доступность и внешнюю доступность вашего приложения.

livenessProbe используется для определения того, работает ли контейнер и может ли он продолжать работать. Если liveness probe не проходит, то kubelet перезапустит контейнер.

readinessProbe используется для определения готовности контейнера принимать трафик. Если readiness probe не проходит, то Kubernetes не будет перенаправлять трафик на контейнер до тех пор, пока readiness probe не начнет проходить.

PostgreSQL can be accessed via port 5432 on the following DNS name from within your cluster:

    postgres-service-postgresql.default.svc.cluster.local - Read/Write connection

To get the password for "postgres" run:

    export POSTGRES_PASSWORD=$(kubectl get secret --namespace default postgres-service-postgresql -o jsonpath="{.data.postgresql-password}" | base64 --decode)

To connect to your database run the following command:

    kubectl run postgres-service-postgresql-client --rm --tty -i --restart='Never' --namespace default --image docker.io/bitnami/postgresql:11.7.0-debian-10-r9 --env="PGPASSWORD=$POSTGRES_PASSWORD" --command -- psql --host postgres-service-postgresql -U postgres -d postgres -p 5432



To connect to your database from outside the cluster execute the following commands:

    kubectl port-forward --namespace default svc/postgres-service-postgresql 5432:5432 &
    PGPASSWORD="$POSTGRES_PASSWORD" psql --host 127.0.0.1 -U postgres -d postgres -p 5432

services:
  mysql:
    image: mysql:8.0
    container_name: mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: ghjfyz
      MYSQL_DATABASE: gallery
      MYSQL_USER: nauths
      MYSQL_PASSWORD: ghjfyz
    volumes:
      - ./mysql-data:/var/lib/mysql
    ports:
      - "3306:3306"
    networks:
      - mysql-network

  phpmyadmin:
    image: phpmyadmin/phpmyadmin
    container_name: phpmyadmin
    restart: always
    depends_on:
      - mysql
    environment:
      PMA_HOST: mysql
      PMA_PORT: 3306
    ports:
      - "8080:80"
    networks:
      - mysql-network

networks:
  mysql-network:
    driver: bridge
